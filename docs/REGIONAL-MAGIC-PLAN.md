# Regional magic as developing geography

## Outcome and boundaries

The user authorized planning and execution after comparing magic refinement with
hydrology: finer magical geography must develop from coarse context, rather than
merely perturbing inherited intensity and naming thresholded patches.

User boundaries: regional maps remain independent; no ancestor or sibling writes,
parent conservation, boundary reconciliation, history replay or seamless zoom.
Preserve all seven systems and their own media, stocks and meetings. Manual
editing, region selection, dynamic cell sizing, backend and recovery are excluded.
This request authorizes local implementation and validation, not publication.

## Sources and implementation choices

- `refinement/inputs.ts` omits published coverage channels. `magic.ts` adjusts
  captured intensity but does not develop sources from captured stocks.
- `refinement/water.ts` and `lakes.ts` establish the useful analogy: distributed
  context and fine terrain produce local structures before geographic extraction.
- ADRs 0004, 0005 and 0007 retain separate system media, fractional coverage and
  realized/latent geography. Canonry's lore and layer bodies supply motivation,
  not a regional execution schedule or named setting requirements.
- Proposal: dedicated regional material development, followed by system-specific
  transport, physical response and the existing classification/publication path.
  Coverage guides local distribution; it is neither uniform weak intensity nor an
  exact numerical obligation to the parent. No generic renewal or history engine.
- Assumption: captured stocks and coverage are available on current maps. Older
  inputs without a channel can use their existing intensity/source context;
  missing information must not fabricate histories or enable absent systems.
